## Why the desktop stays empty

Two things are going on, and only one of them is about wallpapers.

First, Desktop Mode itself is still a developer feature. You turn it on in Developer options — it isn't something a normal user has switched on, and Android doesn't present it as finished.

Second, and this is the actual blocker: Android decides per display whether a wallpaper is allowed to exist there at all. The decision lives in the wallpaper service, in [`WallpaperDisplayHelper`](https://cs.android.com/android/platform/superproject/main/+/main:frameworks/base/services/core/java/com/android/server/wallpaper/WallpaperDisplayHelper.java):

```java
boolean isUsableDisplay(Display display, int clientUid) {
    if (display == null || !display.hasAccess(clientUid)) {
        return false;
    }
    final int displayId = display.getDisplayId();
    if (displayId == DEFAULT_DISPLAY) {
        return true;
    }
    return mWindowManagerInternal.isHomeSupportedOnDisplay(displayId);
}
```

Your phone's built-in screen is `DEFAULT_DISPLAY`, so it returns early and always gets a wallpaper. Every other display has to be one the launcher runs on.

That answer decides whether a wallpaper engine is ever created. [`WallpaperManagerService`](https://cs.android.com/android/platform/superproject/main/+/main:frameworks/base/services/core/java/com/android/server/wallpaper/WallpaperManagerService.java) only builds a `DisplayConnector` — the object that attaches an engine to a screen — for displays that pass the check:

```java
appendConnectorWithCondition(display ->
        mWallpaperDisplayHelper.isUsableDisplay(display, mClientUid));
```

A display that fails is skipped silently. No connector, no engine, no wallpaper. Nothing errors and nothing is logged for you to find.

## So why is it grey?

Because the grey is a fallback, and you're looking at the layer that was supposed to have a wallpaper in it.

When you enter Desktop Mode, Android slides a dedicated activity in behind your windows. [`DesktopWallpaperActivity`](https://cs.android.com/android/platform/superproject/main/+/main:frameworks/base/libs/WindowManager/Shell/src/com/android/wm/shell/desktopmode/DesktopWallpaperActivity.kt) describes itself as:

> A transparent activity used in the desktop mode to show the wallpaper under the freeform windows.

That's the whole job. It's transparent on purpose, it runs fullscreen so the launcher stays hidden, and it's added when you enter desktop and removed when you leave. It doesn't draw a background — it exists so a wallpaper can be seen through it.

Put the two halves together and the grey explains itself. The window that would reveal your wallpaper is present and working. The wallpaper engine behind it was never attached, because the display didn't pass `isUsableDisplay`. What's left is the plain surface underneath, a flat `#A0A0A0` in the recording above.

So the desktop isn't broken and it isn't empty by design. It's a window onto a layer that nothing was allowed to paint.

## It isn't the app

Wallpaper Reactor already handles this case. The Android engine checks whether it's running off the primary screen and keeps rendering when it is:

```kotlin
fun isSecondaryDisplay(): Boolean =
    getCompatDisplayContext().display.displayId != Display.DEFAULT_DISPLAY
```

Every visibility decision in the wallpaper service takes that into account, so the engine stays alive on a display the phone isn't looking at. The wallpaper is running and ready to draw — it simply has nowhere to appear yet.

## When it ships, this works

Android is clearly building toward it. The flag exists, the plumbing exists, and Desktop Mode is a shipped feature on Android 17. The day connected-display wallpaper is switched on for everyone, Wallpaper Reactor needs no new release to take advantage of it — the secondary-display path is already written and tested.

In the meantime live wallpapers work exactly as you'd expect on your phone's own screen, and if you plug into a desktop, the same library is waiting for you on Windows and macOS.
