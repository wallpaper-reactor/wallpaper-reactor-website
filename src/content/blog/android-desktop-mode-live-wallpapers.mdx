## Why

Desktop Mode moves your session onto a display that isn't the phone's built-in screen. In Android's terms that's a secondary display, and wallpaper support there is still gated.

The flag lives in Android's own source, in `DesktopExperienceFlags`:

```java
ENABLE_CONNECTED_DISPLAYS_WALLPAPER(android.app.Flags::enableConnectedDisplaysWallpaper, true,
        android.app.Flags.FLAG_ENABLE_CONNECTED_DISPLAYS_WALLPAPER),
```

That class is documented as holding flags "aiming for developer preview before their release," switched by the `persist.wm.debug.desktop_experience_devopts` system property. Connected-display wallpaper is on the list, which is a fair summary of where the feature sits: built, not switched on for everyone.

## It isn't the app

Wallpaper Reactor already handles this case. The Android engine checks whether it's running off the primary screen and keeps rendering when it is:

```kotlin
fun isSecondaryDisplay(): Boolean =
    getCompatDisplayContext().display.displayId != Display.DEFAULT_DISPLAY
```

Every visibility decision in the wallpaper service takes that into account, so the engine stays alive on a display the phone isn't looking at. The wallpaper is running and ready to draw — it simply has nowhere to appear yet.

## When it ships, this works

Android is clearly building toward it. The flag exists, the plumbing exists, and Desktop Mode is a shipped feature on Android 17. The day connected-display wallpaper is switched on for everyone, Wallpaper Reactor needs no new release to take advantage of it — the secondary-display path is already written and tested.

In the meantime live wallpapers work exactly as you'd expect on your phone's own screen, and if you plug into a desktop, the same library is waiting for you on Windows and macOS.
